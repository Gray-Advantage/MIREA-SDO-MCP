# MCP-сервер для СДО РТУ МИРЭА

Дата: 2026-09-03

## Задача

Дать агенту доступ к СДО РТУ МИРЭА (`online-edu.mirea.ru`, Moodle): список
дисциплин, структура курса, папки, файлы, скачивание, просмотр. На первом
этапе — строго чтение; отправка ответов на задания отложена до момента, когда
у пользователя появится что сдавать.

## Что выяснила разведка

**Локальной формы логина нет.** Кнопка «Студент/преподаватель РТУ МИРЭА» ведёт
на `/auth/oidc/?source=loginpage`, оттуда 302 на Keycloak:

```
https://sso.mirea.ru/realms/mirea/protocol/openid-connect/auth
  ?response_type=code&client_id=moodle&response_mode=form_post&...
```

Дальше пароль и код из почты. Вариант «логин/пароль в `.env`» отпадает.

**Достаточно одной куки.** `MoodleSession` не HttpOnly. Проверено внешним
curl: с кукой `/my/` отдаёт 200, без неё — редирект на `/login/index.php`;
`pluginfile.php` с кукой отдаёт файл. CSRF-токен `sesskey` лежит в HTML любой
страницы (`M.cfg.sesskey`), так что серверу нужна только кука.

**Web services REST включён**, но требует токен, а токен даётся за пароль —
не используем.

**AJAX-RPC `/lib/ajax/service.php`** работает с кукой + sesskey, но только для
функций с `ajax => true`. Доступно и используется:

- `core_course_get_enrolled_courses_by_timeline_classification` — дисциплины;
- `core_courseformat_get_state` — вся структура курса в JSON;
- `core_calendar_get_action_events_by_timesort` — дедлайны.

Закрыто (`servicenotavailable`): `core_course_get_contents`,
`core_enrol_get_users_courses`, всё по оценкам. Эти данные берём разбором HTML.

**Скрытые курсы Moodle не отдаёт в `all`** — это отдельная категория
`hidden`. У пользователя 10 обычных и 4 скрытых; содержимое скрытых читается.
Поэтому `list_courses` доливает их и помечает полем `hidden`.

## Решения

**Авторизация.** `sdo_login` открывает headed Chromium (Playwright) с
постоянным профилем в `~/.mirea-sdo-mcp/browser-profile`, ведёт на страницу
входа и опрашивает вкладки, пока Moodle не начнёт считать нас залогиненными
(нет класса `notloggedin`, есть `M.cfg.sesskey`). Тогда забирает куку в
`session.json` с правами `600`. Учётные данные через сервер не проходят.
Постоянный профиль означает, что Keycloak помнит вход и повторный логин
обычно проходит без кода из почты. Аварийный фолбэк — переменная
`MOODLE_SESSION`, она перебивает сохранённую сессию.

**Два источника данных, одна кука.** JSON-RPC там, где он открыт; разбор HTML
для папок, заданий, оценок, тестов, форумов.

**Индекс элементов.** Инструменты принимают голый `cmid`, но URL в Moodle
содержит тип модуля (`/mod/folder/view.php`). Поэтому строится ленивый индекс
`cmid → (курс, тип, название)` обходом деревьев всех курсов, с TTL 10 минут.

**Кэш перечня файлов.** Полный обход курса стоит десятков запросов (каждая
папка, каждое задание, HEAD на каждый ресурс). Результат кэшируется на 10
минут; холодный проход по всем дисциплинам — около минуты, повторный — секунда.

**Чтение без скачивания.** `read_file` кладёт файл во внутренний кэш и отдаёт
текст только запрошенных страниц, чтобы заглянуть в материал, не засоряя
папку загрузок пользователя. Страницей считается: у PDF — страница, у pptx —
слайд, у xlsx — лист, у остального — кусок ~3000 символов.

## Архитектура

```
src/mirea_sdo_mcp/
  config.py     адреса, пути, таймауты
  auth.py       Playwright-логин, хранение сессии
  client.py     httpx: кука, ретраи, sesskey, RPC, скачивание
  reader.py     постраничное чтение pdf/docx/pptx/xlsx/текста
  server.py     регистрация 24 инструментов
  moodle/
    index.py    cmid → курс/тип/название
    courses.py  список дисциплин, дерево курса, поиск элементов
    files.py    папки, файлы, маски, скачивание
    modules.py  универсальный get_activity
    assignments.py  grades.py  quizzes.py  forums.py
    html.py     общие приёмы разбора
```

Разбор таблиц вынесен в чистые функции (`parse_folder`, `parse_index`,
`parse_overview`, `parse_course_report`), поэтому тесты идут по сохранённым
образцам разметки без сети.

## Границы

Записи нет нигде: ответы не отправляются, попытки тестов не начинаются,
сообщения не публикуются. Из 24 инструментов 19 помечены `readOnlyHint`;
остальные пять пишут только на локальный диск.

## Что осталось непроверенным

Разбор форумов написан по стандартной разметке Moodle, но сверить его с
живыми данными не удалось: на момент разработки во всех 14 доступных курсах
форумы пусты.

## Дальше

Отправка ответов на задания — отдельной задачей, когда появится что сдавать.
Это потребует пересмотра границ (сейчас запись исключена по построению) и
подтверждения действий у пользователя перед каждой отправкой.
