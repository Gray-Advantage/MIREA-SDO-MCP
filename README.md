# MIREA SDO MCP

MCP-сервер для СДО РТУ МИРЭА (`online-edu.mirea.ru`, Moodle). Даёт агенту
доступ к дисциплинам, их структуре, файлам, заданиям, оценкам, тестам и
форумам.

Почти всё — только на чтение. Единственное исключение — отправка ответа на
задание, она вынесена в два отдельных инструмента и требует подтверждения
(см. [Сдача заданий](#сдача-заданий)).

Работает в Claude Code, Claude Desktop, Codex и Cursor.

---

## Установка

Нужен [uv](https://docs.astral.sh/uv/). Если его нет:

```bash
curl -LsSf https://astral.sh/uv/install.sh | sh
```

Дальше одна команда:

```bash
uv tool install --from git+https://github.com/Gray-Advantage/MIREA-SDO-MCP mirea-sdo-mcp
```

Появится команда `mirea-sdo-mcp` (в `~/.local/bin`). Больше ничего ставить не
надо.

Для входа сервер использует уже установленный Google Chrome (или Edge) — это
экономит около 550 МБ. Если системного браузера нет, при первом `sdo_login`
скачается свой Chromium. Каналы задаются через `SDO_BROWSER_CHANNELS`.

Проверить, что всё на месте:

```bash
mirea-sdo-mcp --help 2>/dev/null || command -v mirea-sdo-mcp
```

Если команда не находится, добавь каталог в `PATH`:

```bash
uv tool update-shell && exec $SHELL
```

## Подключение к клиенту

### Claude Code

```bash
claude mcp add mirea-sdo -- mirea-sdo-mcp
```

Проверить: `claude mcp list`. Убрать: `claude mcp remove mirea-sdo`.

### Claude Desktop

Открой `~/Library/Application Support/Claude/claude_desktop_config.json`
(macOS) или `%APPDATA%\Claude\claude_desktop_config.json` (Windows) и добавь:

```json
{
  "mcpServers": {
    "mirea-sdo": {
      "command": "mirea-sdo-mcp"
    }
  }
}
```

Перезапусти приложение.

### Codex

```bash
codex mcp add mirea-sdo -- mirea-sdo-mcp
```

Или руками в `~/.codex/config.toml` (либо `.codex/config.toml` в проекте):

```toml
[mcp_servers.mirea-sdo]
command = "mirea-sdo-mcp"
```

### Cursor

Создай `~/.cursor/mcp.json` (глобально) или `.cursor/mcp.json` (в проекте):

```json
{
  "mcpServers": {
    "mirea-sdo": {
      "command": "mirea-sdo-mcp"
    }
  }
}
```

> Если `mirea-sdo-mcp` не в `PATH` клиента, укажи полный путь — его покажет
> `which mirea-sdo-mcp`. Как запасной вариант годится
> `"command": "uvx", "args": ["--from", "git+https://github.com/Gray-Advantage/MIREA-SDO-MCP", "mirea-sdo-mcp"]`,
> но так сервер стартует заметно дольше.

## Первый вход

Скажи агенту вызвать `sdo_login` (или попроси «войди в СДО»). Откроется окно
браузера на странице входа РТУ МИРЭА — введи логин, пароль и код из почты
прямо там. Дальше всё работает само.

Если системного Chrome нет, при самом первом запуске окно появится не сразу:
сервер сначала скачает собственный Chromium. Это разово.

Когда сессия истечёт, инструменты вернут `error: session_expired` — просто
вызови `sdo_login` ещё раз. Обычно хватает одного клика: профиль браузера
сохраняется, и SSO помнит вход, код из почты второй раз не спрашивают.

### Как устроена авторизация

У СДО нет своей формы входа: кнопка «Студент/преподаватель РТУ МИРЭА» ведёт
на `/auth/oidc/`, оттуда — на Keycloak `sso.mirea.ru`. Логин паролем «из
конфига» там невозможен в принципе.

Поэтому сервер открывает настоящее окно браузера. Учётные данные вводятся в
нём и **через сервер не проходят** — он забирает только куку `MoodleSession`
и кладёт её в `~/.mirea-sdo-mcp/session.json` с правами `600`. Этой куки
достаточно и для страниц, и для скачивания файлов; CSRF-токен `sesskey`
сервер добывает сам со страницы `/my/`.

## Обновления

Сервер сам проверяет релизы GitHub при старте (тихо, раз в 6 часов) и
подмешивает отметку в `sdo_auth_status`.

- `sdo_check_updates` — есть ли новая версия. `force=true` спрашивает GitHub
  заново, минуя кэш.
- `sdo_update` — ставит свежую версию и говорит, что нужен перезапуск.

Способ обновления сервер выбирает сам: установленный через `uv tool`
переустанавливается из git, а локальная копия репозитория обновляется через
`git pull` + `uv sync`.

**Сессия при обновлении не теряется.** Кука и профиль браузера лежат в
`~/.mirea-sdo-mcp`, а переустанавливается только окружение пакета в
`~/.local/share/uv/tools/mirea-sdo-mcp` — эти пути не пересекаются.

Хорошая привычка — раз в сессию попросить агента «проверь обновления СДО-MCP».

Руками то же самое:

```bash
uv tool install --force --from git+https://github.com/Gray-Advantage/MIREA-SDO-MCP mirea-sdo-mcp
```

Отключить проверку: `SDO_UPDATE_CHECK=0`.

## Форма ответов

Инструменты, возвращающие перечни, отдают `{"count": N, "items": [...]}`, а не
голый список — так в ответ помещается служебная информация.

Если вышла новая версия сервера, в любой ответ добавляется поле `_update` с
подсказкой обновиться. Запрос к GitHub при этом в каждый вызов не идёт:
вердикт освежается фоном не чаще раза в 15 минут (`SDO_UPDATE_CHECK_TTL`),
иначе каждый вызов стал бы медленнее и упёрся бы в лимит GitHub.

## Инструменты

Из 29 инструментов 21 помечен `readOnlyHint`. Пишут на локальный диск
скачивание, сессия и обновление. В СДО пишут только два инструмента сдачи
заданий, и оба описаны ниже.

### Сессия и обновления
| Инструмент | Что делает |
|---|---|
| `sdo_login` | Открыть окно браузера и войти через SSO |
| `sdo_auth_status` | Жива ли сессия, под кем вошли, сколько курсов видно |
| `sdo_logout` | Забыть сохранённую сессию локально |
| `sdo_check_updates` | Есть ли новая версия в релизах GitHub |
| `sdo_update` | Поставить свежую версию |

### Дисциплины
| Инструмент | Что делает |
|---|---|
| `list_courses` | Список дисциплин; скрытые включены и помечены `hidden` |
| `get_course` | Дерево курса: секции и элементы внутри них |
| `search_activities` | Поиск элементов по части названия |
| `refresh_index` | Перечитать курсы и сбросить кэши |

### Содержимое
| Инструмент | Что делает |
|---|---|
| `get_activity` | Содержимое любого элемента по `cmid`, тип определяется сам |
| `list_folder` | Файлы папки, включая вложенные подпапки |
| `list_course_files` | Все файлы курса: папки, файлы-ресурсы, вложения к заданиям |
| `search_files` | Поиск файлов по маске по всем дисциплинам |

### Файлы
| Инструмент | Что делает |
|---|---|
| `read_file` | Постраничное чтение **без** скачивания к пользователю |
| `download_file` | Скачать один файл |
| `download_folder` | Скачать папку целиком, сохранив структуру |
| `download_course` | Скачать все материалы курса по секциям |

### Сдача заданий
| Инструмент | Что делает |
|---|---|
| `get_submission_form` | Что задание принимает: лимиты, число файлов (только читает) |
| `stage_assignment_files` | Положить файлы в черновик — **ответ не сдаётся** |
| `submit_assignment` | Сдать на проверку, только с `confirm=true` — **необратимо** |

### Задания, оценки, прочее
| Инструмент | Что делает |
|---|---|
| `list_assignments` | Задания со сроками и состоянием ответа |
| `get_assignment` | Условие, статус сдачи, приложенные файлы |
| `get_deadlines` | Ближайшие дедлайны по всем курсам |
| `get_grades_overview` | Итоговая оценка по каждой дисциплине |
| `get_course_grades` | Постатейный отчёт по одному курсу |
| `list_quizzes` / `get_quiz` | Тесты и их сроки (попытку не начинает) |
| `list_forum_discussions` / `get_forum_discussion` | Форумы и объявления |

## Сдача заданий

Отправка разбита надвое намеренно.

`stage_assignment_files` кладёт файлы в черновичную область Moodle. Это
обратимо и никому не видно: пока не сделан финальный POST, работа не сдана.
Инструмент возвращает `draft_itemid` — его нужно передать дальше.

Учти: **в интерфейсе задания эти файлы не появятся до сдачи.** Черновичная
область привязана к конкретному открытию формы, и когда задание открывают в
браузере, Moodle заводит новый пустой черновик. Проверить закреплённое можно
по ссылкам `draftfile.php`, которые возвращает инструмент.

`submit_assignment` делает финальный POST. **В здешней настройке Moodle стадии
«черновик ответа» нет: сохранение сразу отправляет работу преподавателю.**
Поэтому без `confirm=true` инструмент ничего не делает, а агенту предписано
спросить разрешения у пользователя перед вызовом.

```
stage_assignment_files(cmid=930993, paths=["~/работа.pdf"])
  → draft_itemid=72862223, submitted=false
submit_assignment(cmid=930993, draft_itemid=72862223, confirm=true)
  → submitted=true
```

Лимиты берутся из СДО, а не задаются в коде. `get_submission_form` показывает
предел размера и число файлов, а `stage_assignment_files` проверяет их до
загрузки.

Moodle пишет в форму `maxbytes = 0`, когда своего предела у задания нет — тогда
действует лимит курса, и сервер дочитывает его из настроек курса. Поле
`max_bytes_source` говорит, откуда взято значение: `задание`, `курс` или
`неизвестно`.

## Маски поиска

`search_files` и параметр `pattern` понимают два вида масок:

- glob — `*.pdf`, `Лекция*`, `*2026_2027*` (регистр не важен, путь тоже проверяется);
- регулярное выражение с префиксом `re:` — `re:практич.*\.docx`.

## Чтение файлов

`read_file` кладёт файл во внутренний кэш `~/.mirea-sdo-mcp/cache` и отдаёт
текст только запрошенных страниц, так что заглянуть в лекцию можно, не
засоряя папку загрузок.

Что считается «страницей»: у PDF — настоящие страницы, у `.pptx` — слайды,
у `.xlsx` — листы, у `.docx` и текстовых форматов — куски примерно по 3000
символов. Диапазон задаётся как `3`, `1-5` или `1,4,7-9`; без указания
отдаются первые пять страниц.

Страницы без текстового слоя (сканы) не выдумываются: они перечисляются в
`empty_pages` с пояснением в `note`.

## Настройки через окружение

| Переменная | Назначение | По умолчанию |
|---|---|---|
| `SDO_BASE_URL` | Адрес СДО | `https://online-edu.mirea.ru` |
| `SDO_STATE_DIR` | Где хранить сессию, профиль браузера и кэш | `~/.mirea-sdo-mcp` |
| `SDO_DOWNLOAD_DIR` | Куда качать по умолчанию | `<state>/downloads` |
| `SDO_REQUEST_DELAY` | Пауза между запросами, с | `0.25` |
| `SDO_UPDATE_CHECK` | Проверять обновления при старте | `1` |
| `SDO_UPDATE_REPO` | Откуда брать обновления | `Gray-Advantage/MIREA-SDO-MCP` |
| `SDO_UPDATE_CHECK_TTL` | Как часто освежать вердикт о версии, с | `900` |
| `SDO_BROWSER_CHANNELS` | Системные браузеры для входа; пусто — только свой Chromium | `chrome,msedge` |
| `MOODLE_SESSION` | Кука в обход `sdo_login` (аварийный вариант) | — |

## Разработка

```bash
git clone https://github.com/Gray-Advantage/MIREA-SDO-MCP
cd MIREA-SDO-MCP
uv sync
uv run playwright install chromium
uv run pytest
```

Тесты разбирают образцы реальной разметки СДО из `tests/fixtures`
(обезличенные), сеть при этом не нужна.

Подключить локальную копию вместо установленной:

```bash
claude mcp add mirea-sdo-dev -- uv run --directory "$PWD" mirea-sdo-mcp
```

## Известные ограничения

- **Форумы не проверены на живых данных.** На момент разработки во всех
  доступных курсах форумы были пусты, поэтому разбор списка тем и сообщений
  написан по стандартной разметке Moodle, но вживую не сверялся.
- **Полный обход курса стоит десятков запросов.** `list_course_files` и
  `search_files` заходят в каждую папку, задание и ресурс. Первый проход по
  всем дисциплинам занимает около минуты, дальше десять минут работает кэш
  (`refresh=true` перечитывает).
- **Сканы не распознаются.** Текст берётся из текстового слоя; OCR нет.
- **Промежуточное состояние не видно в интерфейсе.** Закреплённые файлы
  живут в черновичной области, привязанной к открытию формы, и в задании
  появляются только после сдачи. Посмотреть их заранее можно лишь по прямым
  ссылкам `draftfile.php`.
- Часть Moodle API (`core_course_get_contents`, оценки) закрыта для запросов
  из браузера, поэтому эти данные берутся разбором HTML и зависят от вёрстки
  темы `boost_union`.
